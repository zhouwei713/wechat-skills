# 分析指南

每篇文章按五层来分析。前一层由脚本处理，后四层由模型填写。字段名、类型和可选值全部以 `fields.json` 为准，这里只讲怎么判断。

先记住这张表以后的用法：翻选题库的人想知道最近大家在写什么、哪些我能写、我该怎么写得不一样。每个字段都要为这三件事服务，写不出有用的内容就留空，不要凑。

## 读取状态决定能写什么

| 读取状态 | 能填的字段 |
|---|---|
| 已读全文 | 全部字段 |
| 仅卡片（只有标题、摘要、公众号名） | 一句话核心、选题类型、赛道标签、时效性、目标读者、标题公式、钩子词、提到的工具（只写标题和摘要里出现的）、选题簇、匹配度、我的角度、建议标题 |
| 未读取 | 同上，但只能依据标题判断，一句话核心末尾加"（据标题推断）" |

没读到正文就不许写大纲、可带走资产、亮点、空白、文章形态、开头方式。校验脚本会检查，填了会报错。理由很简单，这张表以后是要拿来做决策的，猜出来的大纲比空着更坏事。

## 第一层 基础信息（脚本）

标题、公众号、链接、发布日期、字数、配图数、来源、对标账号、读取状态。模型不用管。

## 第二层 选题本身

**一句话核心** 写清楚这篇解决了读者的什么问题，要具体到能区分同类文章。差的写法是"介绍了 ffmpeg 的用法"，好的写法是"用四行 ffmpeg 滤镜让 AI 生成的视频看起来像实拍"。40 字以内。

**选题类型** 单选。判断依据是读者拿它干什么。

| 类型 | 判断依据 |
|---|---|
| 工具测评 | 评价一个或几个工具好不好用 |
| 教程 | 一步步教会某个操作 |
| 合集 | 列一串工具、提示词、资源 |
| 工作流 | 几个工具串起来完成一件事 |
| 观点 | 表达判断，信息是为观点服务的 |
| 资讯 | 报道新发布、新动态 |
| 案例拆解 | 拆解一个作品、账号、爆款 |

**赛道标签** 多选，最多 3 个，只能从固定选项里选，实在没有合适的才用"其他"。

**时效性** 内容绑定某个新版本、新发布、近期事件的算热点，两周后还有人搜的算常青。

**目标读者** 一句话描述，比如"想用 AI 做短视频但不会剪辑的新手"。

## 第三层 标题

**标题公式** 多选，最多 2 个。

| 公式 | 例子 |
|---|---|
| 数字时效 | 5分钟教你用 WorkFlow 免费做 AI 视频 |
| 对比锚定 | 一款 Flash 模型，开始交付 Opus 5.5 能写出的前端作品 |
| 结果前置 | 用 ffmpeg 去掉 AI 图感 |
| 信息差 | 某某悄悄上线了…… |
| 痛点提问 | 为什么你的 AI 视频一看就是假的？ |
| 清单合集 | 10 个…… |
| 系列编号 | 12 \| 电影质感…… |
| 身份代入 | 普通人 / 宝妈 / 程序员也能…… |
| 反常识 | 别再…… / 其实…… |

**钩子词** 标题里真正勾人的词，原样摘出来，1 到 3 个。比如"免费""5分钟""去掉 AI 图感"。

## 第四层 结构（需要全文）

**文章形态** 工具书型是读者拿来查的手册，合集型是挑着装的清单，工作流型是照着搭的流程，观点型和资讯型按字面意思判断。

**开头方式** 看前三段在干什么。

**大纲** 把小标题按顺序抽出来，每行一个，前面加序号。原文没有小标题的，按段落意思概括成 4 到 8 行。

## 第五层 借鉴与差异化

**提到的工具** 文中出现的工具、模型、开源项目，用官方名称，比如"Seedance 2.0""ffmpeg"。

**可带走资产** 原文给出的提示词、命令、配置、参数，**逐字照抄**，校验脚本会去正文里比对。多段资产之间空一行。原文没给就留空。

**亮点** 最多两条，写值得学的具体做法，比如"每个滤镜参数后面都配了一张前后对比图"。别写"内容详实""干货满满"这种空话。

**空白** 这篇没讲到、讲浅了、或者明显有问题的地方，最多三条。这是差异化选题的来源，要写具体，比如"只讲了滤镜参数，没讲不同生成模型的画面需要不同参数"。

**我的角度** 结合 config 里的 `profile`，写一句"如果我来写，会怎么写得不一样"。角度要从空白里长出来。

**建议标题** 按 profile 里的风格要求给一个标题。

**匹配度** 1 到 5 分。

| 分数 | 含义 |
|---|---|
| 5 | 正好在我的赛道，有明确空白，我有条件写 |
| 4 | 在我的赛道，角度需要再想 |
| 3 | 相关但不是重点 |
| 2 | 只能当素材参考 |
| 1 | 和我基本无关 |

profile 的 `not_doing` 里列出的方向，匹配度最多给 2。

## 选题簇

这是整张表最有价值的字段，用来发现撞题和热点。

1. 先读 `work/existing.json` 里已有记录的选题簇和一句话核心
2. 新文章和某个已有簇说的是同一件事（同一个工具的同一个用法、同一个事件、同一个问题），就沿用那个簇的名字，一字不改
3. 都不像就新建一个簇，命名用"对象 + 动作"，8 到 14 个字，比如"WorkFlow 做 AI 视频""ffmpeg 去 AI 感"
4. 同一批新文章之间也要互相比对

判断宽严的标准是，两篇文章放在一起，读者会不会觉得"这俩说的是一回事"。同样讲 Seedance，一篇讲人脸一致性、一篇讲运镜，算两个簇。

## 文字风格

* 口语、具体，像写给自己看的备忘
* 不用破折号，不用"不是……而是……"，少用冒号，别写排比
* 数字用阿拉伯数字
